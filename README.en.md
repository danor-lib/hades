# @danor-lib/hades
![Version](https://img.shields.io/github/package-json/v/danor-lib/hades?style=flat-square)
[![License](https://img.shields.io/github/license/danor-lib/hades?style=flat-square)](https://opensource.org/license/mit)

A logging library based on [log4js-node](https://github.com/log4js-node/log4js-node), pre‑packaged with a unified output format, terminal highlighting styles, file rotation, and other default features.

## Design Philosophy

Traditional logging libraries usually provide only basic level filtering and output channels. The design goals of `Hades` are:

- **Unified format** — Every log follows a three‑part structure: `where → what → result` (where it happened, what was done, and what the outcome was), making logs both readable and searchable.
- **Semantic highlighting** — Control‑character syntaxes such as `~[field]` (terms/nouns), `~{value}` (values) and `~<value|value-type>` (value + value type) automatically highlight key information in the terminal.
- **Ready to use** — By default, logs are output to both console and files; file rotation by size is enabled automatically. No extra configuration is needed for a production‑ready logging experience.
- **Context reuse** — `Melinoe` (preset `where`) and `Zagreus` (preset `where` + `what`) reduce repetitive parameter passing within the same context.

## Basic Example

```javascript
import { Hades } from '@danor-lib/hades';

// --- Create a Hades instance ---
const G = new Hades({ name: 'my-app', dirn: './logs' });

// --- Log using where → what → result ---
G.info('Database', 'connect', '✔ ~[target]~{localhost:3306}');
// Output: [01-07 14:30:00:123][INFO] Database => connect  ✔ target[localhost:3306]

G.warn('Cache', 'low hit rate', '~[hit rate]~{35%}');
// Output: [01-07 14:30:01:456][WARN] Cache => low hit rate  ~hit rate[35%]

// --- Log errors (stack is automatically saved to <name>.stack.log) ---
G.error('~[API]~{api/version}', 'request failed', new Error('connection timeout'));
// Console: [01-07 14:30:02:789][ERROR] API[api/version] => request failed  ✘ Error occurred --> connection timeout
// File my-app.stack.log: full stack trace

// --- Inline update (progress bar scenario) ---
for (let i = 0; i <= 100; i += 10) {
  G.infoU('Task', 'processing', `~{${i}%}`);
}
G.infoD('Task', 'done', '✔');
```

## Log Format

All Hades logs follow the uniform format:

```
[time][level] where => what  result
```

- `where` — location / module where the log occurs
- `what` — action / event performed
- `result` — outcome / additional information

> **Recommendation**: Regardless of the log level, it is advisable to organise log content following the `where → what → result` structure. This makes logs visually consistent, easy to read, and searchable.

## Core Concepts

### Log Levels and When to Use Them

Hades provides 7 log levels, each with a clear use case and corresponding terminal colour:

| Level   | Method   | Colour  | Use Case                                                                                                                                           |
| :------ | :------- | :------ | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| `trace` | `.trace` | Blue    | High‑frequency low‑level data, e.g., loop indices. Should not remain in production code; remove immediately after debugging.                       |
| `debug` | `.debug` | Cyan    | Low‑frequency computed results, such as function return values or non‑critical heartbeat info.                                                     |
| `info`  | `.info`  | Green   | Routine summaries or expected, handleable exceptional data.                                                                                        |
| `warn`  | `.warn`  | Yellow  | Operational data that may lead to exceptions but the program can recover, e.g., database connection timeout during startup (can be retried later). |
| `error` | `.error` | Red     | Exceptional logic and unexpected errors, e.g., missing required fields when inserting into a database, causing business interruption.              |
| `fatal` | `.fatal` | Magenta | Critical logs that cause the program to exit, e.g., unhandled exceptions or file read/write errors.                                                |
| `mark`  | `.mark`  | Grey    | Necessary statements unrelated to runtime state. Always output unless logging is turned off, e.g., copyright notices and warnings.                 |

### Emphasis Format `~[field]`, `~{value}` and `~<value|value-type>`

Hades comes with three built‑in emphasis formats based on control characters, which are automatically rendered as styled text in the terminal:

| Syntax                 | Purpose             | Rendering (highlight on)                       | Rendering (highlight off)                         |
| :--------------------- | :------------------ | :--------------------------------------------- | :------------------------------------------------ |
| `~[field]`             | Field / noun / term | Underline + bold                               | Plain text (`~[` and `]` removed)                 |
| `~{value}`             | Value / data        | White + wrapped in square brackets             | Wrapped in square brackets (`~{` and `}` removed) |
| `~<value\|value-type>` | Value + value type  | Value in white + value type in grey + brackets | Wrapped in square brackets (`~<` and `>` removed) |

The value‑type variant starts with `~<` and ends with `>`; inside it, the value and the value type are separated by `|`. Filling the value type with the `vof` type identifier is recommended (see `vtof` / `wvt` below).

```javascript
G.info('Server', 'start', '✔ ~[listen port]~{8080}');
// Highlight on:  [time][INFO] Server => start  ✔ listen port(underline+bold)[8080](white)
// Highlight off: [time][INFO] Server => start  ✔ listen port[8080]

G.info('Server', 'start', '✔ ~[listen port]~<8080|number>');
// Highlight on:  [time][INFO] Server => start  ✔ listen port(underline+bold)[8080(white)|number(grey)]
// Highlight off: [time][INFO] Server => start  ✔ listen port[8080|number]
```

- When highlighting is disabled (`willHighlight: false`), the control characters are automatically stripped, leaving plain semantic text.
- To output a literal `~[`, `~{` or `~<`, escape it with a backslash: `\~[` `\~{` `\~<`.
- It is generally not recommended to use `~[field]` alone in the `where` part unless combined with a value.

### Emphasis Helpers `wf` / `wv` / `wvt` / `vtof`

Manually assembling control characters is error‑prone, so Hades additionally exports four pure functions that generate emphasis fragments:

```javascript
import { Hades, vtof, wf, wv, wvt } from '@danor-lib/hades';
```

| Function      | Purpose                                                                             | Syntax generated       |
| :------------ | :---------------------------------------------------------------------------------- | :--------------------- |
| `wf(field)`   | Wraps a **field** / noun / term                                                     | `~[field]`             |
| `wv(value)`   | Wraps a **value**                                                                   | `~{value}`             |
| `wvt(value)`  | Wraps a value **together with its `vof` type**                                      | `~<value\|value-type>` |
| `vtof(value)` | Returns the value combined with its `vof` type, **without** any emphasis characters | None (plain string)    |

```javascript
wf('listen port');    // '~[listen port]'
wv(8080);             // '~{8080}'

wvt(8080);            // '~<8080|number>'
wvt('abc');           // '~<abc|string(3)>'
wvt([1, 2]);          // '~<1,2|array(2)>'
wvt(null);            // '~<null|null>'
wvt({ a: 1 });        // '~<{"a":1}|object>'

vtof(8080);           // '8080|number'
vtof('abc');          // 'abc|string(3)'
vtof([1, 2]);         // '1,2|array(2)'
vtof(null);           // 'null|null'
```

> `wf`, `wv` and `wvt` correspond to the three emphasis formats above: `~[field]` (underline + bold), `~{value}` (white + square brackets) and `~<value|value-type>` (value in white + value type in grey + square brackets).
> `vtof` is the underlying implementation of `wvt`; it returns a `value|value-type` string without control characters, and can be used on its own outside of logging.
> The value type comes from `vof` of [`@danor-lib/error`](https://www.npmjs.com/package/@danor-lib/error), e.g. `number`, `string(3)`, `array(2)`, `null`. Objects are `JSON.stringify`-ed first and fall back to `<stringify-failed object>` when serialisation fails.

These functions are also attached to `Hades` / `Melinoe` / `Zagreus` instances (`vtof` is not attached), so they can be used directly inside an existing logging context:

```javascript
const G = new Hades();

G.info('Server', 'start', `✔ ${wf('listen port')}${wvt(8080)}`);
G.info('Server', 'start', `✔ ${G.wf('listen port')}${G.wvt(8080)}`);
// Both are equivalent, both output: ✔ listen port[8080|number]

const dbLog = G.where('Database');
dbLog.info('connect', `${dbLog.wvt('localhost:3306')}`);
```

### Output Modes

Each log level has three output variants:

| Suffix | Example     | Behaviour                                      | Use Case                                |
| :----- | :---------- | :--------------------------------------------- | :-------------------------------------- |
| none   | `.debug()`  | Normal output, ends with newline               | Regular logging                         |
| `U`    | `.debugU()` | Inline update (carriage return, no newline)    | Progress bars, real‑time status updates |
| `D`    | `.debugD()` | End inline update (newline, ends current line) | Used with `U` series to mark completion |

```javascript
// Progress bar example
for (let i = 0; i <= 100; i += 20) {
  G.infoU('Download', 'progress', `~{${i}%}`);  // refreshes on the same line
}
G.infoD('Download', 'done', '✔');               // ends with a newline
```

### Errors and Stack Logs

- `.error()` / `.fatal()` support passing an `Error` object directly.
- When an `Error` is passed, only the error message summary is printed to the console; the full stack is **automatically written** to the `<name>.stack.log` file.
- Supports `Error.cause` chains: if the error has a `cause` property, the entire chain is output recursively.

```javascript
const cause = new Error('DNS resolution failed');
const error = new Error('connection timeout', { cause });

G.error('~[Network]', 'request failed', error);
// Console:
//   [time][ERROR] Network => request failed  ✘ Error occurred --> connection timeout
//      --> DNS resolution failed
// File logs/my-app.stack.log:
//   Error: connection timeout
//       at ...
//   Caused by: Error: DNS resolution failed
//       at ...
```

### `fatalE` — Log and Exit

`.fatalE(code, where, what, ...infos)` logs a fatal message and then immediately calls `process.exit(code)`.

```javascript
G.fatalE(1, 'Startup', '~[config] missing', 'required field ~{db.host}');
// Logs fatal message, then exits with code 1
```

## Constructor

### `new Hades(options?)`

Creates a Hades instance.

- **Parameters** `options` `{Object}` — Optional. All properties are optional.

| Option                   | Type      | Default                | Description                                                                                           |
| :----------------------- | :-------- | :--------------------- | :---------------------------------------------------------------------------------------------------- |
| `name`                   | `string`  | `'default'`            | Instance name, also used as the log file name prefix.                                                 |
| `level`                  | `string`  | `'all'`                | Minimum log level; messages below this level are not output.                                          |
| `dirn`                   | `string`  | `process.cwd()`        | Directory for log files. If not specified, **logs are not written to files** — only console output.   |
| `eol`                    | `string`  | `os.EOL`               | End‑of‑line character for log files.                                                                  |
| `templateTime`           | `string`  | `'MM-DD HH:mm:ss:SSS'` | Time format template; syntax from [dayjs](https://day.js.org/docs/en/display/format).                 |
| `sizeFileLogMax`         | `number`  | `20971520` (20MB)      | Maximum size in bytes for a single log file; rotation occurs when exceeded.                           |
| `numberFileLogBackupMax` | `number`  | `0`                    | Number of old log files to keep; `0` means none.                                                      |
| `willHighlight`          | `boolean` | `true`                 | Whether to enable highlighting for `~[field]` / `~{value}` / `~<value\|value-type>` emphasis formats. |
| `willColorLevel`         | `boolean` | `true`                 | Whether to output different colours based on log level.                                               |
| `willOutputInitInfo`     | `boolean` | `true`                 | Whether to output an info log after initialisation completes.                                         |
| `willConsoleOutputError` | `boolean` | `false`                | Whether to output error stacks to the console (by default only written to file).                      |
| `willInitImmediate`      | `boolean` | `true`                 | Whether to initialise immediately after construction. If `false`, call `.init()` manually.            |

```javascript
// Default configuration
const G = new Hades();

// Custom name and directory
const G = new Hades({ name: 'api-server', dirn: './logs' });

// Console only (no file output)
const G = new Hades({ dirn: '' });

// Delayed initialisation
const G = new Hades({ willInitImmediate: false });
G.level = 'debug';  // modify configuration before initialisation
G.init();
```

### `init()`

Initialises the logging system (configures appenders, creates the Logger). Automatically called if `willInitImmediate` is `true` during construction.

- **Returns**: The `Hades` instance for chaining.

```javascript
const log = new Hades({ willInitImmediate: false });
// ... modify configuration ...
G.init();
```

### `reload()`

Asynchronously reloads the logging system. Shuts down the existing Logger and re‑initialises.

- **Returns**: `Promise<Hades>`

```javascript
// SIGHUP signal handling
process.on('SIGHUP', () => G.reload());
```

### Logging Methods

All logging methods share the signature `(where, what, ...infos)`:

```javascript
G.trace(where, what, ...infos);  // Blue
G.debug(where, what, ...infos);  // Cyan
G.info(where, what, ...infos);   // Green
G.warn(where, what, ...infos);   // Yellow
G.error(where, what, ...infos);  // Red
G.fatal(where, what, ...infos);  // Magenta
G.mark(where, what, ...infos);   // Grey
```

### Inline Update Methods (`U` / `D` variants)

Each level has corresponding `U` (update) and `D` (done) variants for progress bars and other scenarios requiring updates on the same line:

```javascript
// U series: inline update
G.debugU(where, what, ...infos);  // carriage return without newline, refreshes current line
// D series: end update
G.debugD(where, what, ...infos);  // outputs and then newline, ends inline update
```

7 levels × 2 variants = 14 methods: `traceU/D`, `debugU/D`, `infoU/D`, `warnU/D`, `errorU/D`, `fatalU/D`, `markU/D`.

### `fatalE(code, where, what, ...infos)`

Logs a fatal message and immediately exits the process.

- **Parameters**:
  - `code` `{number}` — Exit code.
  - `where` `{string}`
  - `what` `{string}`
  - `...infos` `{any[]}`

```javascript
G.fatalE(1, '~[Core]', 'unrecoverable error', new Error('out of memory'));
// Logs then process.exit(1)
```

## Melinoe and Zagreus — Context Reuse

When logging frequently within the same context, repeatedly passing `where` and `what` becomes tedious. `Melinoe` and `Zagreus` are lightweight wrappers around Hades that preset these parameters.

### `Melinoe` — Preset `where`

Obtain a Melinoe instance via `G.where(where)`. Its logging methods omit the `where` parameter:

```javascript
const dbLog = G.where('Database');

dbLog.info('connect', '~[target]~{localhost:3306}');
dbLog.error('query failed', new Error('syntax error'));
// Equivalent to G.info('Database', 'connect', '~[target]~{localhost:3306}')
```

`Melinoe` also supports `.what(what)` to further chain and produce a `Zagreus` instance:

```javascript
const dbConnectLog = G.where('Database').what('connect');
dbConnectLog.info('~[target]~{localhost:3306}');
```

### `Zagreus` — Preset `where` + `what`

Obtain a Zagreus instance via `G.what(where, what)` or `melinoe.what(what)`. Its logging methods **only need `...infos`**:

```javascript
const dbConnectLog = G.what('Database', 'connect');

dbConnectLog.info('~[target]~{localhost:3306}');
dbConnectLog.error(new Error('timeout'));
// Equivalent to G.info('Database', 'connect', '~[target]~{localhost:3306}')
// Equivalent to G.error('Database', 'connect', new Error('timeout'))
```

> Both `Melinoe` and `Zagreus` support the full set of logging methods: normal (`.info`), inline update (`.infoU`), end update (`.infoD`), and `fatalE`, and also carry the emphasis helpers `.wf` / `.wv` / `.wvt`.

## Advanced Features

### 1. File Rotation

When file output is enabled (by specifying `dirn`), Hades automatically enables size‑based rotation:

- `sizeFileLogMax` controls the maximum file size (default 20MB).
- `numberFileLogBackupMax` controls the number of old files to keep (default `0`, meaning none).
- When the log file exceeds the size limit, a new file is created automatically; old files are named `<name>.log.<n>` (e.g., `my-app.log.1`).

```javascript
const log = new Hades({
  name: 'server',
  dirn: './logs',
  sizeFileLogMax: 1024 * 1024 * 10,  // 10MB
  numberFileLogBackupMax: 5,          // keep up to 5 old files
});
```

Generated file structure:

```
logs/
├── server.log          ← current log
├── server.log.1        ← previous
├── server.log.2        ← older
├── ...
├── server.log.5
└── server.stack.log    ← error stack log
```

### 2. Disabling Emphasis Highlighting

In terminals that do not support ANSI control characters (e.g., some CI environments, file redirection), it is recommended to disable highlighting:

```javascript
const log = new Hades({ willHighlight: false });
```

When disabled, the control characters `~[field]`, `~{value}` and `~<value|value-type>` are stripped, leaving only plain semantic text.

### 3. Level Colours

`willColorLevel` (default `true`) controls whether different log levels are output with different colours. The colour mapping for each level is shown in the “Log Levels and When to Use Them” table above.

```javascript
// Disable colours (for terminals without colour support)
const log = new Hades({ willColorLevel: false });
```

### 4. i18n Text Customisation (`texts`)

`Hades.texts` controls fixed text strings used in logs and can be replaced at any time to suit different languages:

```javascript
const log = new Hades({
  texts: {
    name: 'Log',
    init: 'Initialised',
    'error-encounter': 'Error encountered',
    level: {
      ALL: 'ALL', TRACE: 'TRACE', DEBUG: 'DEBUG',
      INFO: 'INFO', WARN: 'WARN', ERROR: 'ERROR',
      FATAL: 'FATAL', MARK: 'MARK', OFF: 'OFF',
    },
  },
});
```

You can also replace them at runtime:

```javascript
G.texts['error-encounter'] = 'Exception occurred';
G.texts.level.ERROR = 'CRITICAL';
```

### 5. Console‑Only Output

Set `dirn` to an empty string or omit it (default is `process.cwd()`) to **only output to the console** without writing to files:

```javascript
// No file output
const log = new Hades({ dirn: '' });
```

### 6. Custom Time Format

Use `templateTime` to customise the timestamp format in logs. The syntax follows [dayjs](https://day.js.org/docs/en/display/format):

```javascript
const log = new Hades({
  templateTime: 'YYYY-MM-DD HH:mm:ss',  // ISO style
  // templateTime: 'HH:mm:ss',          // time only
});
```

### 7. Error Chains (`Error.cause`)

When an `Error` object is passed to an `error`‑level log, Hades automatically expands the `cause` chain:

```javascript
const root = new Error('file not found');
const mid = new Error('config load failed', { cause: root });
const top = new Error('startup failed', { cause: mid });

G.error('~[Startup]', 'initialisation error', top);
// Output:
//   [time][ERROR] Startup => initialisation error  ✘ Error occurred --> startup failed
//      --> config load failed
//      --> file not found
```

### 8. Escaping Special Characters

To output literal `~[`, `~{` or `~<`, simply escape them with a backslash:

```javascript
G.info('Note', 'syntax', 'use \\~[term\\] and \\~{value\\}');
// Output: [time][INFO] Note => syntax  use ~[term] and ~{value}
```
